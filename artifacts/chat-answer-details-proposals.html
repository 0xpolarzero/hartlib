Quotes and full debug logs for chat answers

This document proposes two later additions to the answer details surface. It does not change the API, database, retention, or authorization contract.

Scope guard: the current UI change covers the unframed answer column, fixed progress rail, and closed sources disclosure. The quote and debug-log changes below are designs only. No source text or new log data is exposed by this proposal.

1. Actual supporting quotes

Show a short quote beside an inline citation only when the authorized citation record includes the exact supporting text. Keep the answer text and citation marker unchanged. The quote row must never fetch source text in the browser or infer a quote from a title, URL, page range, search snippet, or answer wording.

What exists now

  • PublicCitationRecord and PublicSourceRecord include an exact normalized quote for web sources. The durable assistant_message_sources.locator also stores that quote and its integrity hash.
  • Document records expose identity, title, URL, and selected ranges in the current shared schema, but no document text. The durable locator binds the ranges to an immutable document version and hash; the browser cannot reconstruct the text from that contract.
  • Earlier-chat records expose a message ID and memory records expose a memory plus revision ID. Their public ranges are empty. The durable source-use rows keep private ranges, while the message or memory text stays outside the public citation projection.
  • Web search snippets are not answer evidence. Only the fetched, normalized quotation selected by the web path is durable answer evidence.

What needs backend work

  • For document, earlier-chat, and memory citations, the server must reconstruct the exact text from the immutable version/message/revision and the saved ranges, then authorize it for the current viewer before serialization.
  • Add a versioned citation field such as quote: { text } | null to the authorized citation projection. Keep the current web quote compatible during migration; do not add quote text to the sources-read list unless the product asks for it.
  • Return null when no safe quote can be reconstructed or the viewer is not allowed to see it. Do not return a reason that could reveal restricted content or authorization state.
  • Bound quote length and encoding in the server contract, preserve the existing source key/order contract, add replay and authorization tests, and update the data-access and runtime specs before enabling it. Keep integrity hashes server-side for verification; never serialize them in the public quote projection.

Proposed empty state

Use one precise, content-free message for every unavailable case: “Quote unavailable for this source.” Do not show an empty quote mark, a made-up excerpt, a range, a provider snippet, or a link that suggests the missing text is present. Keep the row visible only when the user opens the citation detail.

2. Expandable full debug logs

Offer an owner-only, closed-by-default “Debug details” disclosure beneath the current safe diagnostics. The view should help a user or support worker explain a slow, retried, compacted, or failed run without turning the browser into a prompt, retrieval, or provider console.

Safe fields to maximize

  • Run identity and public timestamps when the API supplies them; terminal state, retryable flag, normalized error code/category/message, and last SSE sequence.
  • Five-stage history with status, bounded duration, attempt, topic label when already public, and safe result/source counts.
  • Context fit summary: mode, compaction ran or not, consumer count, input/output allowance counts, and usable-token counts already carried by context_ready.
  • Source summary by count and kind: read, cited, and read-but-uncited. Keep source names, URLs, ranges, quotes, and identities out of this log view.
  • Memory outcome counts, model/web usage counts and bytes when already present in the public usage events, answer-start and finalization status, and a clear “stream ended” row.

Never include

  • Prompts, resolved questions, search queries, answer text, source text, quotations, ranges, hashes, titles, URLs, or source identities.
  • Provider request/response payloads, credentials, authorization headers, raw provider errors, stack traces, SQL, private memory content, or restricted support data.
  • Smithers state, workflow snapshots, internal task graphs, raw coordinates, or fields that let the browser infer a hidden model/provider call.
  • Data from another user, a shared chat’s private memory lane, an unauthorized source, or a source that the current viewer cannot still open.

Recommended information hierarchy

  1. Level 1 — outcome: status, run ID, terminal time, retry action when allowed, and a short normalized failure message.
  2. Level 2 — stage rail: the same five fixed labels as the active answer rail, with status, attempt, duration, and safe counts.
  3. Level 3 — run summary: context fit/compaction, source read/cited counts, memory counts, usage totals, and SSE cursor.
  4. Level 4 — event history: an expandable chronological list of safe transitions. Keep it closed by default and make each row readable by keyboard and screen reader.
  5. Level 5 — support handoff: offer a copyable safe run ID and normalized failure code only. Do not add a raw-log download.

Proposed API boundary

Prefer an authorized, owner/shared-viewer checked endpoint such as GET /v1/ai-runs/:runId/debug. It should return a strict public schema assembled from ai_run_events, durable usage rows, final source/citation counts, and locked run timestamps. The endpoint must enforce the same chat visibility boundary as SSE, omit restricted fields before serialization, and return an honest unavailable state when terminal events or retained details have expired. A later support-only endpoint may use restricted access, but it must not be reused by the client debug view.

Safety and rollout notes

  • Do not infer quote availability from a source URL or range.
  • Use a generic unavailable quote state to avoid authorization leaks.
  • Keep memory quote support owner-only; shared chats cannot expose saved-memory records.
  • Make debug details closed by default and keyboard reachable.
  • Use bounded counts and lengths; reject unknown fields at the API boundary.
  • Do not make a terminal SSE replay window look like durable history.
  • Keep source order and citation ordinals unchanged.
  • Test reload, expired events, failed retries, and shared-viewer boundaries.
